From the skeleton data extracted during a sequence (by get_splitted_sequences_boundaries() or get_skeletons_in_splitted_sequences() ) or by defining temporal boundaries, extract the data from sensors during this sequence.

Parameters
skeleton_dataThe skeleton data extracted from a sequence with the functions get_splitted_sequences_boundaries() or get_skeletons_in_splitted_sequences().
start_timeIf the skeleton data is not provided, give the starting time (in ms) of a sequence to extract the sensors data.
end_timeIf the skeleton data is not provided, give the ending time (in ms) of a sequence to extract the sensors data.
id_sequenceIf none of the above is provided, just give the ID of the sequence and it will fetch the good starting/ending time. (But I'm pretty sure this method is not the best possible...)
time_offsetThe time (in sec) that is added before and after the camera stopped seen somebody. In our experiments, the sensors had a greater field of view so it is important to get some offset time.
time_between_sequencesIf using the "id_sequence", it's the needed time (in sec) between two timestamps for which we consider that doesn't belong in the same sequence.
sensor_heightProviding this parameter let the system filter to get only sequences where the sensors were in a certain position. For now the choice is "hips" or "ankles". But maybe we will add "one_sided", or even "other_sensors_hips", "other_sensors_ankles", etc...

Parameters
sequence_filenameIf given a rosbag file (recording from the camera), the start and end limits are extracted from it. But rosbag files are not really used anymore...
start_timeThe lower limit at which we can detect a sequence (in ms)
end_timeThe upper limit at which we can detect a sequence (in ms)
merge_skeleton_idsUseless

Otherwise, return an array of these tuple for each sequence found.

Function to get the temporal boundaries of sequences during which a person is walking and sequences where nobody is walking.

This can be used to create a dataset for a classifier that do person detection and maybe (with improvement in this code, I guess) an estimator of number of persons.

Parameters
start_timeThe lower limit at which we can detect a sequence (in ms)
end_timeThe upper limit at which we can detect a sequence (in ms)
time_between_sequencesThe needed time (in sec) between two timestamps for which we consider that doesn't belong in the same sequence.
ignore_small_sequencesIf some skeletons are detected in a sequence but that this sequence is smaller than a threshold (in sec), ignore it.
Returns
A dictionary with keys:
  • 'presence': an array of tuple (start_time, end_time) of sequences with someone walking
  • 'no_presence': an array of tuple(start_time, end_time) of sequences without anybody
See also
If you don't care for absence sequences, see get_splitted_sequences_boundaries().

Insert coordinates of a skeleton by passing the array like the one that is created by the HumanSkeleton class.

See also
HumanSkeleton
Parameters
coord2DThe coordinates on the screen that you want to save
coord3DThe coordinates on the real world that you want to save
timestampThe timestamp at which these coordinates has been recorded
skeleton_idThe ID of the person in the sequence. Most processes takes only the sequences with the person ID == 0, so try to have all skeleton on a sequence with a unique person to have an ID = 0.
deviceThe name of the device that recorded the person. You then are able to filter sequences filmed by a camera D400 or the L515, or any new camera you are using.
ignore_None_valuesSet to False if you want to insert a NULL value for keypoints that aren't seen on screen. I'm not really sure about the changes needed if you insert NULL values, so the best is to keep this argument to True, I guess...
send_immediatelySet to True to send these coordinates to InfluxDB (which can take up to 0.5 second) or set it to False to wait to have more data and send all the data at once.
walking_speedIf already computed, you can store the estimation of the walking speed.
footsteps_widthIf already computed, you can store the estimation of the footsteps width.
number_of_footstepsIf already computed, you can store the estimation of the number of footsteps.
stride_lengthIf already computed, you can store the estimation of the stride length.
step_lengthIf already computed, you can store the estimation of the step length.
timestamp_unitThe unit used as timestamp ('ms' or 's')
raw_coord_2DThe coordinates without any translation/rotation, in case the transformation had an math error
raw_coord_3DThe coordinates without any translation/rotation, in case the transformation had an math error
